# 도메인 · 패키지 설계

ComfoziAI 구매 증빙 인박스 — 구매 점검(ComfoziAI 가격 점검) **앞단 2단계**의 백엔드.

- `structuring` (구조화) : 기계 단계 — 입력을 구조화 후보로 만들어 영속
- `inspection` (품목점검) : 사람 단계 — 구조화 결과를 검수·승인/반려 *(상세 추후)*

## 패키지 트리

```
com.doq.comfozi
├── structuring                 [구조화 · 기계 단계 · 파이프라인]
│   ├── ingestion               파일 업로드(→Mongo) · XLSX/CSV 파싱 · 수기 등록 · 원본 근거(SourceRef)
│   ├── mapping                 raw row → 후보 필드 매핑 (관찰값 세팅)
│   ├── normalization           품목 정규화: 사전 조회 → 규칙 → "데이터 부족"
│   │                             └ 품목 마스터 사전 = 참조 데이터
│   └── detection               예외 탐지 규칙 엔진: 누락 · 중복 · 규격 · 단위 → exception flags
│                                 output → "구조화 결과"(관찰값 + 플래그) → inspection으로 인계·영속
│
└── inspection                  [품목점검 · 사람 단계]  ← 구조화 결과가 영속되는 지점
                                  상세(애그리거트 · review · changelog · export)는 추후 설계
```

## 저장소 매핑

| 저장소 | 소유 | 내용 |
|---|---|---|
| MongoDB | `structuring.ingestion` | 업로드 원본 파일 |
| PostgreSQL (JPA) | `inspection` | 구조화 결과 애그리거트 + 상태 · 변경 이력 |

## 경계 (기계 → 사람)

`structuring`이 "구조화 결과"(관찰값 + 예외 플래그)를 산출하면 → `inspection`이 이를 받아
애그리거트로 **영속**(초기 상태 `new` + 플래그 부착). 이 지점이 두 루트의 인계 경계이며,
이번 설계 범위는 여기(영속 단계)까지다.
